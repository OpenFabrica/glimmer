# 模型假设与验证尺子

输入法里「模型可能能做的事」不止整句重排一件。每一件在动手之前都要先回答：用什么指标算成功、指标从哪些数据算、
现在的基线是多少。基线算不出来的假设不立项。这份文件记每个假设的尺子；输入日志（`input-log.jsonl`）按这里的需要定格式，
回放评测（`glimmer-cli --replay`）按这里的指标出报告。

## 原则

- 日志记的是**情境、给的、做的、事后反馈**四件事，不是某个模型的特征。字段与模型无关，任何排序 / 预测 / 纠正类假设都能回放验证。
- 漏记的补不回来，多记的代价很低：情境数据只要隐私成本接近零就记。
- **不记**应用里的光标前文（含用户没通过微明打的内容）、逐键时间戳、Secure Input 期间的任何东西。
- 每个假设先写指标与基线，再改代码；改完在**同一份冻结日志**上比（日志是活的，两次复制的不一样）。
- 日志验不了的（延迟、UI 感受、反事实「当时给了 X 会不会选」）只能自己用；反事实只在 X 恰好出现在用户最终文本时近似。

## 日志格式 v1

一行一条 JSON，`t` 是本机时间戳，`event` 是事件名；读端跳过不认识的事件与字段，以后加字段不升版本。

| 事件 | 何时 | 字段 |
|---|---|---|
| `session` | 输入法启动、日志开关打开时 | `v` 格式版本、`version` 输入法版本、`platform`、`model` 本地整句模型开没开、`scheme` 双拼方案 |
| `commit` | 每次上屏 | 原有：`id` `scope` `keys` `pinyin` `corrected` `text` `source` `index` `top`（一页 9 条）`scheme` `english`；新增：`rescored` 候选顺序经过神经重排、`app` 应用标识、`pages` 翻了几页、`ms` 首键到上屏的毫秒 |
| `retract` | 上屏后整个退格删掉、同段拼音改选了别的 | `of` `text` `chosen` |
| `retype` | 组句里退格重打，最终键串与第一次退格前不同；或上屏后删掉重打了不同的键 | `before` `after` `of`（对应的上屏 `id`） |
| `passthrough` | 组句外直打的标点 / 回车 / 空格，攒到下一次上屏或边界时写 | `text` |
| `prediction` | 云端联想结果到达并展示 | `scope` `words` `sentence` |
| `break` | 上文链断开（切应用、失焦、清空） | `app` 新应用标识 |

## 英文输入（`--eval-english`）

回放里英文上屏只有一两百条，量不出英文排序的好坏，所以英文另用打字模拟：拿一段英文文本，在英文模式下逐字母敲、每键看候选，
规则（计键、什么时候选、七组各量什么）写死在 `apps/cli/src/eval/english/mod.rs` 的文件头，摘要见 `notes/crate-notes.md` 的 apps/cli。只算候选列表里真有、按键真能选到的候选。

- **语料**：`tools/corpus/english_corpus.py` 下载五个来源（FineWeb、SODA、WildChat-1M 用户轮次、Ubuntu IRC、oasst2），先去重，再按整篇文档 / 整段对话切成四份：
  训练（`data/corpus/en/train/`，只给 `english-ngram` 统计语言模型）、调参集 `dev`、测试集 `test`、验收集 `final`（`data/eval/english/<份>/{chat,tech,writing}.txt`，每份每类约 2 万词）。
  切分结果与各文件 sha256 在 `data/eval/english/MANIFEST.tsv`。
- **三份怎么用**：扫常数只用调参集（`constant-sweep.md`「英文候选常数」）；测试集每做完一步报一次数；验收集全程不看，只在全部做完时跑一次，作为最终数字。
- **怎么跑**（配置副本里 `[predict] enabled = false`，种子 1）：

  ```bash
  cargo build --release -p glimmer-cli
  target/release/glimmer-cli --config <配置副本> --eval-english data/eval/english/test/chat.txt --misses 0
  # 只跑几组：--eval-english-groups complete,typo,prefix；量没有英文模型的降级：--lm-en /不存在
  ```

- **基线**冻结在 `data/eval/english/baseline/`（改造前的二进制、词表、配置、两张用例表，校验和 `SHA256SUMS`，完整输出在 `out/`），跑法写在 `BASELINE.md`。

## 下一词预测（`--eval-english` 的 `predict` 组）

英文词上屏、敲了空格之后显示一个预测词，Tab 接受（行为见 `design/candidate-ui.md`「英文模式候选」）。尺子是 `--eval-english` 的第七组 `predict`，规则写在 `apps/cli/src/eval/english/predict/mod.rs` 文件头，摘要在 `notes/crate-notes.md` 的 apps/cli：
与补全组一样逐词敲，每个词开敲前问一次 Engine 给不给预测；第一个预测与目标词逐字相同就按 Tab（计 1 键），否则照补全组敲、不加键。

- **取预测耗时**：调参集聊天 p50 0.03 ms、p95 0.22 ms；测试集与验收集六份文本 p95 0.22–0.26 ms、最大 0.60 ms（`notes/performance.md`）。
- **尺子的局限**：
  - 猜错不扣键。真实里弹出一个不对的词会让人分心、多看一眼，尺子量不出这份「打扰」，所以阈值按「出现率 vs 精确率」定，没有按省键率定。
  - 命中后紧跟标点要退格（Tab 带出的空格），尺子不计这一键，只单独报次数；含预测的省键率因此略高估，聊天文本高估得最多。
  - 只模拟 Tab 接受第一个；「如果给三个」不进省键率。
  - 5 秒时效在模拟里不会触发；真实里停下来想的时候预测会过期。
  - 文本里的上文都是这一遍真的上屏的词，不读应用前文；句首不出（真实里也不出）。

## 已知的尺子偏差

- 日志里「选了」的整句多半是当时按空格接受的基线自己的输出：模型对、日志错的例子不少（输入狂 → 输入框）。
  整句质量以冻结评测集 `data/eval/sentences.tsv` 为准（见 `docs/notes/neural-rescoring.md`），回放只看词级与个人学习。
- 2026-09-12 以前的日志有一半是空的 `raw` 行（壳每次回车 / 失焦都调一次 `take_raw`），读端要跳过 `keys` 与 `text` 都空的行。
- 回放里原样上屏（`raw`）也要走一遍 `take_raw`：个人英文词（`gist`）与「这个串不纠」都是从那里学的，跳过它英文首选低 10 个点（72.5% → 82.9%），
  那不是排序的问题，是尺子没学。2026-09-12 起回放这么做。
- 整句「不在候选」328 条的构成（2026-09-12）：16 条是 微明（词库没有的专名，个人词该学但回放从零起）；294 条与现在首选同长、只是同音换字
